# راهنمای همراه نصب بستهٔ ویندوز SolverScout 2.1.0rc3

نصب تمیز و راه‌اندازی تک‌نمونهٔ ویندوز **PASS** است. setup یک‌بار با مصرف واقعی ۱۰۰۲ ارزیابی موفق شد؛ doctor، شروع سرویس، رابط، توقف عادی و راه‌اندازی مجدد نیز موفق‌اند. محیط نصب Python 3.12.3 و Windows 11 build 22631 AMD64 است.

## هویت بسته

- فایل: `p_mc_optimizer-2.1.0rc3.zip`
- SHA-256: `94e88d45658676a1f9f9e62474d4db3bbe5c1f998c6085f4f266da6dced9e760`
- کامیت منبع در `MANIFEST.json`: `32e222e21550f0b881c7e54f180043c7589c13bc`
- مرجع منتشرشده: [کامیت بسته در GitHub](https://github.com/payamshoartajahmadi-lab/SolverScout/commit/32e222e21550f0b881c7e54f180043c7589c13bc)، در تاریخچهٔ شاخهٔ `fix/windows-u1-report-binding`.
- کد آزموده‌شدهٔ گیت آفلاین rc3: `7ca14742dc34933b1c4868f113412aacc59f1f70`؛ تفاوت محتوایی تا کامیت بسته فقط چهار سند است.

این راهنما همراه همان ZIP است و فایل‌های داخل آن را تغییر نمی‌دهد. چون کد اجرایی تغییر نکرده، گیت کامل برای این نصب دوباره اجرا نشد. نتیجهٔ گیت آفلاین rc3، ۱۰۲۳ موفق و یک کنارگذاشته‌شده، و ۹۶۵ آزمون موفق پیشین، نتایج تاریخی مستقل‌اند.

## نصب مستقل در ویندوز

Python 3.12 نسخهٔ ۶۴بیتی و دسترسی اینترنت برای دریافت وابستگی‌های قفل‌شده لازم است. مسیرهای این بررسی `G:\SSrc3-01\app` برای برنامه، `G:\SSrc3-01\app\.venv` برای محیط مجازی تازه و `G:\SSrc3-01\data` برای دادهٔ مستقل هستند. در رایانهٔ مقصد می‌توان همین ساختار را در مسیر کوتاه و قابل نوشتن دیگری ساخت؛ در همهٔ فرمان‌ها مسیر داده را یکسان جایگزین کنید.

پیش از نصب، همهٔ نمونه‌های در حال اجرای SolverScout را با فرمان `stop` از نصب و مسیر دادهٔ خودشان متوقف کنید. فایل ZIP را در پوشهٔ تازهٔ برنامه استخراج کنید؛ `.venv` یا دیتابیس نصب دیگر را به آن منتقل نکنید. در PowerShell همان پوشه:

```powershell
Set-Location 'G:\SSrc3-01\app'
.\scripts\setup.bat
.\scripts\doctor.bat --data-dir 'G:\SSrc3-01\data'
.\scripts\start.bat --data-dir 'G:\SSrc3-01\data'
```

`setup.bat` محیط ویندوز را می‌سازد، وابستگی‌های `requirements.lock` را نصب می‌کند و یک smoke عددی با سقف ۱۰۰۲ ارزیابی در دادهٔ موقت اجرا می‌کند. آن را برای بازکردن روزانهٔ برنامه تکرار نکنید. در صورت خطا ابتدا خروجی همان تلاش را بررسی کنید؛ اجرای دوبارهٔ setup می‌تواند smoke دیگری مصرف کند.

نشانی واقعی رابط در خروجی start چاپ می‌شود. در این نصب رابط `http://127.0.0.1:8501` و API محلی `http://127.0.0.1:8765` سالم‌اند. موفقیت start را با بازشدن رابط و سلامت سرویس بررسی کنید. وضعیت «مدل تنظیم نشده» در نصب تازه طبیعی است و مانع بازشدن رابط محلی نیست.

## اجرای روزانه، توقف و شروع دوباره

فقط **یک نمونهٔ SolverScout در هر زمان** اجرا کنید؛ این محدودیت برای مسیر داده یا پورت متفاوت نیز در این ویندوز برقرار است. عوض‌کردن پورت مجوز اجرای هم‌زمان نمونهٔ دوم نیست. مسیر دادهٔ نصب قبلی را حذف یا بازنشانی نکنید.

```powershell
Set-Location 'G:\SSrc3-01\app'
.\scripts\start.bat --data-dir 'G:\SSrc3-01\data'
```

برای توقف عادی همان نصب:

```powershell
.\.venv\Scripts\python.exe -m p_mc_optimizer stop --data-dir 'G:\SSrc3-01\data'
```

پس از توقف کامل، همان فرمان start را برای راه‌اندازی مجدد اجرا کنید. بستن تب مرورگر جایگزین stop نیست. اگر `NUMERIC_POLICY_ENVIRONMENT_MISMATCH` یا خطای تعیین fingerprint عددی در اجرای تک‌نمونه ظاهر شد، آن را خطای نصب ثبت و علت را بررسی کنید؛ گواهی محیط یا کنترل اعتبار را تغییر ندهید.

## تنظیم کلید API در مقصد

کلید فقط در رابط «تنظیمات ← اتصال مدل زبانی» وارد می‌شود. نشانی سرویس، مدل و کلید شخصی را تنظیم و گزینهٔ «مخزن امن سیستم‌عامل» را برای نگهداری کلید انتخاب کنید. کلید را در چت، Git، گزارش، پوشهٔ برنامه یا ZIP قرار ندهید. کلید نصب دیگر همراه این بسته منتقل نمی‌شود.

بررسی نصب حاضر هیچ ورود کلید، تست اتصال یا تماس واقعی مدل انجام نمی‌دهد. تست اتصال و استفادهٔ بعدی از مدل تماس واقعی محسوب می‌شوند و باید جداگانه مجاز و ثبت شوند. آماده‌سازی عددی شش روش و اجرای مثال‌های پذیرش نیز جزو این بررسی نصب نیستند.

## دامنهٔ نتیجه و حفظ تاریخچه

نتیجهٔ این مرحله فقط نصب تمیز و راه‌اندازی تک‌نمونه در ویندوز را پوشش می‌دهد. پذیرش مک، اجرای کامل تازهٔ U1/U2 یا آماده‌بودن دادهٔ تازه برای دموی دانشگاهی از این نتیجه استنباط نمی‌شود. معیار AC14 نصب تمیز مک همچنان تکمیل‌نشده است؛ نتیجهٔ تاریخی کمپین rc2، گزارش mixed قدیمی U1 و مصرف‌های پیشین تغییر نمی‌کنند. پذیرش گزارش بازتولیدشدهٔ U1 در rc3 بر محاسبات ذخیره‌شده نیز نتیجهٔ مستقل قبلی است.

مصرف واقعی این مرحله: یک smoke با دقیقاً ۱۰۰۲ ارزیابی؛ صفر تماس مدل، صفر تست اتصال، صفر آماده‌سازی عددی گسترده و صفر حل تازهٔ U1/U2. دادهٔ مستقل هیچ job، گزارش، trial، تماس مدل، پروفایل، qualification یا همگام‌سازی منبع ثبت‌شده ندارد؛ کلید خالی است و دادهٔ خصوصی منتقل نشده است.

صفحهٔ خانه و تنظیمات در عرض‌های ۱۴۴۰ و ۳۹۰ پیکسل بدون سرریز افقی یا خطای JavaScript باز شدند. پس از توقف عادی، مالک نمونه حذف و رابط و API غیرفعال شدند؛ پس از راه‌اندازی دوباره، هر دو سرویس پاسخ سالم دادند و doctor موفق بود. `NUMERIC_POLICY_ENVIRONMENT_MISMATCH` در این نصب تک‌نمونه تکرار نشد. علت مشکل اجرای هم‌زمان قبلی همچنان حل نشده است؛ محدودیت یک نمونه در هر زمان برقرار می‌ماند.

فایل‌های اجرایی بسته، داده‌های اصلی و شواهد پیشین حفظ شده‌اند. وضعیت کلی تحویل **NOT_READY** باقی می‌ماند، چون معیار AC14 نصب تمیز مک تکمیل نشده است. موفقیت ویندوز جایگزین پذیرش مک یا اجرای کامل تازهٔ U1/U2 نیست.
