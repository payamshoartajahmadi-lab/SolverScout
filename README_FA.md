# SolverScout

سامانهٔ محلی انتخاب و آزمایش الگوریتم‌های بهینه‌سازی، با نام پیشین P_MC.

این برنامه برای آزمایش انتخاب الگوریتم روی مسائل پیوستهٔ قطعی و تک‌هدفه ساخته شده است. دامنهٔ نسخهٔ ۱ شامل ۲ تا ۳۰ متغیر حقیقی با کران متناهی و بدون قید عمومی است. چهار روش ثبت‌شدهٔ ABC، PSO، DE و CMA-ES واقعاً در یک فرایند عددی جداگانه اجرا می‌شوند. برنامه بهترین مشاهدهٔ معتبر در بودجه را با دو ارزیابی تازه بررسی می‌کند. وضعیت بهینگی سراسری همواره `not_certified` است.

## نصب و راه‌اندازی

Python ۳٫۱۲ را نصب کنید و ZIP را در پوشه‌ای قابل نوشتن استخراج کنید. دریافت وابستگی‌های قفل‌شده در مرحلهٔ نصب به اینترنت نیاز دارد. نصب و راه‌اندازی محلی در macOS روی arm64 آزمایش می‌شود. وضعیت واقعی هر پلتفرم در `TEST_RESULTS.md` ثبت شده است.

```sh
chmod +x scripts/*.sh
./scripts/setup.sh
./scripts/start.sh
```

اگر Python ۳٫۱۲ در PATH نیست، مسیر مفسر را با `PMC_PYTHON312` مشخص کنید. در Windows 11 فرمان‌ها `scripts\setup.bat` و `scripts\start.bat` هستند. در macOS و Linux همان wrapperهای POSIX استفاده می‌شوند. در زمان نصب یک حل نمونه در مسیر موقت جدا انجام می‌شود.

نشانی رابط `http://127.0.0.1:8501` و نشانی API محلی `http://127.0.0.1:8765` است. با `./scripts/doctor.sh` مسیر داده و نسخه‌ها را ببینید. برای توقف `./scripts/stop.sh` را اجرا کنید. نمونهٔ تغییر پورت در `examples/config.example.json` است. گزینه‌های `--data-dir` و `--config` را به فرمان مربوط بدهید. برای مثال `./scripts/start.sh --data-dir "/path/to/data" --config examples/config.example.json`. برای توقف همان `--data-dir` را استفاده کنید.

## تنظیم مدل زبانی

در «تنظیمات مدل زبانی»، OpenAI یا سرویس سفارشی سازگار با Chat Completions را انتخاب کنید. برای حالت سفارشی، نشانی پایهٔ HTTPS، حالت خروجی و نام پارامتر سقف توکن را تعیین کنید. مدل دقیق را وارد کنید. سپس تنظیمات، کلید شخصی و آزمون اتصال را جداگانه ثبت کنید. آزمون اتصال یک درخواست کوتاه خارجی و احتمالاً هزینه‌دار است.

کلید پیش‌فرض در حافظهٔ فرایند API نگهداری می‌شود. وقتی مخزن امن سیستم‌عامل در دسترس باشد، نگهداری دائمی را می‌توانید صریحاً انتخاب کنید. برای کلید نشست پس از راه‌اندازی مجدد دوباره آن را ثبت و اتصال را آزمایش کنید. تغییر مدل یا تنظیمات ارائه‌دهنده نسخهٔ تازه‌ای می‌سازد. دکمهٔ «رفع اتصال همین اجرا» به تنظیمات ثابت همان اجرا متصل است.

برای خطای احراز هویت، کلید و سطح دسترسی حساب را بررسی کنید. برای خطای مدل یا endpoint، شناسهٔ دقیق مدل، نشانی پایه و شیوهٔ خروجی را با تنظیمات ارائه‌دهنده تطبیق دهید. خطای ۴۲۹ به محدودیت نرخ یا اعتبار مربوط می‌شود. خطای مهلت یا ارتباط می‌تواند با بررسی شبکه و آزمون دوباره رفع شود. پیش از تلاش مجدد، وضعیت مصرف را در حساب API بررسی کنید.

صورت‌بندی متن و خلاصهٔ شواهد انتخاب و توضیح به مقصد نشان‌داده‌شده ارسال می‌شوند. پردازش تابع هدف، داده‌های اجرا و رابط روی رایانهٔ کاربر هستند. هزینه و دسترسی مدل تابع حسابی است که کاربر تنظیم می‌کند.

## حل و گزارش

در «مسئلهٔ جدید» حالت متن، فرم ساخت‌یافته، JSON یا نمونه را انتخاب کنید. برای شروع بدون API، فایل `examples/quadratic_2d.json` و سیاست «خط پایه · روش ثابت» را انتخاب کنید. مثال بیشینه‌سازی و چهار تابع آموزشی نیز در `examples/` هستند. محدودیت فایل JSON، ۲۵۶ کیبی‌بایت و محدودیت متن، ۱۶۰۰۰ نویسه است. عبارت تابع از دستور زبان محدود استفاده می‌کند. توان `**`، ضرب `*` و زاویه‌ها بر حسب رادیان هستند. طول، تعداد گره و عمق عبارت به‌ترتیب ۴۰۹۶، ۵۱۲ و ۳۲ محدود است.

برای حل زبانی، متن `examples/natural_language_fa.txt` را ارسال کنید. مدل، کران‌ها و شواهد استخراج را در «اجرای حل ← مدل مسئله» ببینید. اگر اطلاعات لازم کم باشد، پرسش‌های همان پیش‌نویس یا ورود مدل کامل به‌صورت JSON در دسترس‌اند. بعد از مصرف سهم صورت‌بند، تکمیل ساخت‌یافته همچنان قابل استفاده است.

در «اجرای حل» مرحله، مصرف FE، وضعیت Trialها و دکمهٔ لغو را ببینید. در نتایج، الگوریتم منتخب و منشأ نقطهٔ گزارش‌شده مستقل نمایش داده می‌شوند. نمودار بهترین امتیاز کمینه‌سازی را بر حسب تعداد فراخوانی واقعی نشان می‌دهد. برای بیشینه‌سازی امتیاز برابر منفی مقدار تابع است. مقدار هدف در جدول و گزارش، جهت اصلی مسئله را حفظ می‌کند.

گزارش از تاریخچه نیز در دسترس است. `report.json` دادهٔ مرجع، `report.html` گزارش مستقل قابل خواندن آفلاین و `trials.csv` دادهٔ اجراهای الگوریتمی است. تاریخچهٔ ارزیابی را می‌توان در رابط به CSV تبدیل کرد. فیلد متنی CSV با آغاز مشابه فرمول با یک تک‌نقل‌قول محافظت می‌شود.

## اجرای خط فرمان

پس از نصب در macOS یا Linux:

```sh
.venv/bin/python -m p_mc_optimizer solve --problem examples/quadratic_2d.json --policy fixed_solver --solver de.original
.venv/bin/python -m p_mc_optimizer benchmark --manifest examples/benchmark_smoke.json
.venv/bin/python -m p_mc_optimizer package --output dist/
```

در Windows از `.venv\Scripts\python.exe` استفاده کنید. حل و benchmark خط فرمان فقط با ورودی ساخت‌یافته و سیاست‌های خط پایه اجرا می‌شوند. اگر رابط مالک مسیر داده باشد، برای حل خط فرمان مسیر دادهٔ دیگری بدهید. صفحهٔ «آزمایش پژوهشی» با profile آزموده‌شده یک مسئلهٔ نمونه را با یک یا دو بذر در یک خط پایه و یک سیاست مشاور مقایسه می‌کند. هر Job گزارش مستقل دارد و manifest و شناسه‌های مقایسه قابل دانلود هستند. مجموعهٔ پژوهشی بزرگ جداگانه در `examples/benchmark_research.json` است و فقط با فراخوانی صریح اجرا می‌شود.

کدهای خروج ۰ برای موفقیت، ۲ برای ورودی نامعتبر، ۳ برای پیش‌نیاز یا محیط، ۴ برای خطای اجرا یا اعتبارسنجی و ۱۳۰ برای وقفهٔ کاربر هستند. داده‌ها در مسیر نمایش‌داده‌شدهٔ `doctor` نگهداری می‌شوند. آنجا SQLite، فایل‌های گزارش، checkpoint گردش‌کار و لاگ محلی قرار دارند. استخراج نسخهٔ تازه روی پوشهٔ سورس، مسیر دادهٔ کاربر را تغییر نمی‌دهد.
